# Signal Reducers v0.1.0a1 — experimental alpha

The first experimental source release targets **Apple Silicon macOS with CPython 3.14**. Original project code and documentation use **0BSD**; dependency distributions, downloaded model weights, Redis, and hosted services retain their own terms.

Signal Reducers uses transient Redis transport, CPU Laya routing, independent OpenRouter reducer workers, immutable captured observations, and a hosted DREX decision gate. System 1 selects `none`, `some`, or `extra` thinking for one GPT-5.1 call per escalation. Lifecycle changes remain subject to complete atomic validation. There are no application-set completion budgets, System 2 tool loops, continuations, or automatic retries.

This release corrects fractional error-rate interpretation (`0.45 = 45%`) and makes typed source facts authoritative over conflicting summary prose. Captured attempt history prevents the gate from selecting previously attempted requests after terminal operations and reviewed results leave later batches. Installation now includes the synthetic routing corpus as package data and uses the Hugging Face user cache for downloaded checkpoints.

Validation passed **250 conformance tests with zero skips**, **ten fixture workflows**, **sixteen targeted live numeric checks**, and **one integrated live workflow with zero observed lifecycle violations**. The [dated verification record](../qualification/release-0.1.0a1.md) describes factual review, request counts, installation checks, and measurement limits separately from [historical qualification](../qualification/2026-10-12.md).

CPU throughput, transient queue expiry, and broader live-model quality remain experimental limitations. A successful paced workflow does not clear the original throughput target or establish a fresh ten-workflow qualification. Generated prose can add unsupported interpretations and needs factual review. Simulated video is synthetic metadata, not real-media perception.

Use the [setup guide](../../RUNNING.md) for fixture/live operation and the [release procedure](../RELEASING.md) for reproducible checks. Source, wheel, source distribution, and SHA-256 checksums are prepared locally for review. Publication is a separate step; no repository or package has been uploaded.
