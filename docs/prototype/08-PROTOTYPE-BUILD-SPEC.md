# Signal Reducers — authoritative P0 build specification

**Version 2.0 · Approved model allocation:** local CPU Laya routing; OpenRouter DREX gate and hosted reducer/System 2 calls.

This is the implementation baseline for the eight current prototype documents. Earlier conceptual drafts are privately archived. Code completion, artifact release verification, and live qualification are separate statuses.

The 2026-10-12 pre-cleanup evaluation received a prototype-specific owner exception for the measured Laya routing error rate only. Original CPU throughput and nine-of-ten combined runtime-and-factual quality requirements remain in force. See [historical measurements](../qualification/2026-10-12.md) and [current release verification](../qualification/release-0.1.0a1.md). This experimental alpha does not claim full qualification.

## 1. Objective and demonstration

Build a single-operator Python 3.14 service that reduces repetitive telemetry, fragmented conversation, and synthetic delayed video. The complete demo publishes 100 healthy repeats, degradation while video buffers, a fragmented submitted diagnosis request, a single System 2 answer, healthy recovery, scene corrections/retractions, and visible incomplete/model-failure cases.

Only the gate runtime changes acknowledgement or resolution. A successful diagnosis answers the question; it cannot claim to repair health.

Required features F01–F08 cover transport, CPU routing, three reducers, state, lifecycle, System 1, System 2, and CLI/qualification. [Scope](03-PROTOTYPE-SCOPE.md) records exclusions.

## 2. Architecture and model allocation

One asyncio process owns all application state and scheduling; external Redis provides transient transport. Laya inference runs in a serial CPU executor. Async HTTP has independent slots for three reducers, System 1 and System 2, at most five simultaneous hosted requests.

| Component | Model/API | Runtime behavior |
|---|---|---|
| Router | `convaiinnovations/laya-typed-decisions`, pinned revision | CPU, eager, four threads, one batched prediction with three independent destination choices |
| Reducers | `openai/gpt-4.1-mini`, OpenRouter chat/completions | Strict schema summary/intent; no reasoning parameter |
| System 1 | `nace-ai/drex-v1.5`, OpenRouter systemone | Closed decisions compiled into GateDecision; no generation parameters |
| System 2 | `openai/gpt-5.1`, OpenRouter chat/completions | One strict-schema call with selected none/low/high effort |

Dependencies are Pydantic, Redis client, httpx, Laya/PyTorch and pytest tooling. Config is TOML/environment. `OPENROUTER_API_KEY` is environment-only. Incompatible capabilities fail readiness; fixture adapters are never substituted automatically.

## 3. Signals and Redis

Signals keep UUID, schema 1.0, source/event IDs, source sequence, modality, payload, MIME, source timestamp and intake timestamp. Source IDs are bounded to 256 UTF-8 bytes, MIME to 128, sequence to an integer 0 through 2^63-1; booleans are not counts. Source timestamps require a timezone and normalize UTC. Intake replaces received_at.

Payload is immutable canonical JSON or exact bytes, at most **200,000 bytes inclusive**, JSON depth at most 32, no NaN/infinity/non-string keys. Decoding JSON returns detached copies. Each independent admission gets a separate receipt UUID even if signal IDs repeat.

Wire framing is `SR1\0`, big-endian 32-bit header length, canonical header, and payload bytes. Header limit is 8,192 bytes. Publication accepts at most 100 records / 4 MiB and is all-or-none. Empty publication is a no-op.

A fresh run UUID names queue/owner keys. Atomic claim rejects an existing namespace. The owner token has a 600-second lease, renewed every 60 seconds. Atomic Lua admission requires a live owner and enforces 1,000 queued records; queue idle TTL is 600 seconds. Redis is loopback, no persistence, noeviction, maxmemory 256 MiB. Admission reports accepted/rejected/unavailable/outcome_unknown; unknown outcomes are never automatically retried.

BLPOP is destructive. Corrupt records and records older than 60 seconds are counted and discarded; popped values are never restored. Shutdown deletes only keys owned by its token.

## 4. CPU routing

Fixed destinations: conversation, telemetry, simulated_video. Input uses metadata, canonical payload preview up to 2,048 UTF-8 bytes, explicit truncation flag, five previous same-source outcomes, and registry descriptions. Binary previews are absent. Envelope metadata remains descriptive evidence; routing does not alter original signals or grant producer metadata lifecycle authority. Null sources have no shared history; the history LRU has at most 128 sources.

Load the pinned Laya revision once from the standard Hugging Face user cache. Release artifacts contain no weights. Ask three two-option choices and select a destination at positive probability >=0.5. Zero and multiple selections are valid. Definitions may be supplied through questions rather than duplicated in signal evidence. Use max_len 8192 / head_max_len 256; preflight complete state and option text, reject any internal truncation/collapse or invalid probability response. Inference deadline is five seconds. Timeout marks unhealthy and stops further pops; there is no rule/model fallback.

Fan-out uses independent bounded mailbox offers; a full destination does not roll back another delivery. Record predictions and successful deliveries separately. Preserve complete immutable payloads.

No fine-tuning in P0. Bundle the synthetic routing corpus as package data. Use 240 development and 80 held-out examples with disjoint scenario families, multi/no-destination cases, fragments, synthetic binary envelopes, unrelated sources, and predicted rolling history. Exclude the demo from evaluation data. Held-out targets: per-label recall >=.95, micro precision >=.90, exact-set >=.90, no-destination specificity >=.90. Initial throughput qualification is one typical signal/second; report actual p95 and memory.

## 5. Reducer protocols

Each worker has a 100-record / 16 MiB mailbox-plus-active/assembly budget, one serial processing task, at most 128 subjects, and a bound writer. Thirty-second inference deadlines exclude buffering. A failure clears affected incomplete work, exposes a safe error, and preserves prior committed state. Structural errors do not fabricate model observations.

Telemetry requires source/sequence and typed service/status/metrics/note. Status is ok/degraded/down, error_rate is a finite fraction in [0,1] (0.45 means 45%), queue_depth integer [0,2^63-1], note <=256 bytes. Subject is source/service. Ignore late sequences; gaps mark incomplete coverage. Changed facts trigger one summary and a snapshot; status transitions add an event atomically. Identical facts only refresh freshness, never inference or semantic state.

Conversation requires source/sequence, message_id, replace/append/submit and text. Source/subject IDs follow bounded ASCII identifier rules. One active message per source, <=1,024 UTF-8 bytes. Full-known replace establishes completeness; a gap breaks it until a new replacement. Ordered empty-text submit emits committed message event/current snapshot. Submitted IDs cannot reopen. A changed draft flushes provisionally after 500 ms; expiry after five seconds never commits it. Bare text stays incomplete. Preserve full text; the model supplies intent only as semantic enrichment.

Synthetic video requires VIDEO and MIME application/vnd.signal-reducers.sim-video+json with bytes carrying service/scene/revision metadata. Three contiguous agreeing packets form a segment only when their intake-owned `received_at` span (maximum minus minimum) is at most one second. `source_seq` remains the ordering authority; timestamps only bound coverage. Serial routing delay does not change that input span. Bound delivery/assembly waiting separately by the first intake expiry (`received_at + signal_max_age`, normally 60 seconds), using a monotonic timer and never allowing more than `signal_max_age` of additional waiting. Already expired input fails immediately. `simulation_input_window_exceeded` and `simulation_delivery_expired` distinguish invalid input coverage from downstream waiting expiry. Delay complete processing 500 ms, then summarize. Normal scenes emit snapshot/event. Reflection corrects held stalled lineages to clear; retraction targets current corrected leaves. Missing targets or incomplete segments never invent a scene. This is not real video interpretation.

Activity exposes idle/buffering/processing/failed, queued/assembled counts, active 0/1, timestamps and safe error. Only status changes can wake the gate; count/freshness updates cannot.

## 6. State, batches and authority

Observation fields include immutable identity, reducer/subject/subject sequence, kind/finality/code/content/facts, revision target, confidence, evidence receipt/signal pairs and timestamps. Text <=1,024 bytes; facts object <=512 bytes/depth eight; evidence <=32. Runtime supplies IDs/provenance/finality and preserves typed source facts. Reducer and System 2 prompts explicitly define fractional error-rate units and make structured facts authoritative over conflicting notes or generated summaries; numerical answer accuracy still needs independent assessment.

Revisions target same-area same-subject live leaves, ancestry <=8, with corrected/retracted finality. Historical revisions cannot overwrite newer independent snapshot lineages. Retraction has no rollback. Duplicate identical update IDs are idempotent; conflicting reuse and stale sequences reject the entire group.

Consumption is PENDING→PRESENTED→ACKNOWLEDGED. Resolution is separately UNASSESSED→NO_ACTION_REQUIRED/UNRESOLVED/RESOLVED; it never returns to UNASSESSED. Assessment changes require reasons and captured basis. An informational request resolves only with successful associated result or withdrawal. Unhealthy telemetry resolves only with newer current committed healthy same-subject evidence or withdrawal.

A short lock protects atomic updates, presentation, and gate commits. State version advances on mutations; semantic/input generations exclude bookkeeping. Pin current, unacknowledged, unassessed, unresolved, active/context and required lineage records. Cap at 10,000 records /32 MiB; evict only safe terminal unpinned records or reject atomically.

Frozen batches select up to four oldest unreviewed result groups with targets/evidence/ancestry, 16 new, eight rotating unresolved, eight relevant snapshots, and 32 unique records. Include all activity, active operations and deferred counts. Captured attempted-request IDs identify previously reserved initiating events even after reviewed terminal operations/results are omitted; DREX cannot offer them as fresh operation candidates. Pack against exact DREX whole-request size <=12,000 UTF-8 bytes. Mandatory groups are complete or deferred; no silent field truncation. Pagination requires acknowledgement/result-review/assessment progress and cannot spin on unchanged unresolved work.

## 7. System 1 and operations

DREX questions cover WAIT/ACKNOWLEDGE/ACT_STATUS/ESCALATE_NONE/SOME/EXTRA, initiating request, acknowledgement, resolution, basis and result review. Offer captured IDs and valid options only. Terminal, provisional and retracted targets offer KEEP only; a current-message snapshot is context, while its submitted event is the initiating request. Omit a basis question only when NONE is its sole admissible value; real evidence candidates retain a separate typed question. The adapter supplies fixed explanations and compiles answers into GateDecision; independent model selections must form one valid decision before any mutation. Exact request packing preserves all captured facts and provenance.

One evaluation at a time; coalesce 100 ms up to500 ms. No count-only/idle/unresolved polling. WAIT permits one five-second follow-up; failure permits one delayed retry before parking until new evidence/recheck. Clear/capture wakes under lock.

Validate the whole decision before mutation: exact batch membership, limits <=16 dispositions/8 targets, evidence/domain transitions, current applicability, tool arguments and initiator deduplication. ACT/ESCALATE need exactly one current committed conversation event and unresolved targets. One primary operation per evaluation and one attempted primary operation per submitted request. Reserve before execution; launch failures become results. Replaying a decision cannot repeat execution.

ACT only reads get_processing_status. System 2 has one active request, no queue or tools. Escalation captures <=24,000 bytes of immutable context and carries runtime correlation plus required thinking_level. None/some/extra map to none/low/high effort; exclude reasoning output. **Do not send max_tokens, max_completion_tokens, or reasoning.max_tokens.** Ninety-second deadline; exactly one HTTP attempt, no continuation/repair/retry/effort increase.

Results carry runtime operation/batch/targets, status success/partial/failed/timeout/cancelled, text <=1,024 bytes, data <=512 bytes/depth eight, <=8 captured evidence IDs, safe error/times/context version/applicability. Reject wrong correlation and discard terminal late responses. Results cannot write dispositions. Keep <=128 operations/results with active/unreviewed pins, pruning reviewed terminal entries only.

## 8. CLI, diagnostics, acceptance

Commands: check (readiness, no paid inference), check --probe-models, evaluate-router, run --run-id, publish --file, demo --mode fixture|live --output, demo --mode live --runs 10. Interactive run supports status/recheck/quit. Publisher JSON files <=8 MiB carry payload_json or payload_base64, exactly one. Demo creates its own dedicated Redis unless --redis-url is supplied.

Private outputs are summary.json, trace.jsonl capped10 MiB, final-state.json, plus qualification reports. Record model/provider/config/dataset hashes, per-tier calls/usage/latency, losses/errors, and evidence. Standard errors redact keys/provider bodies/reasoning. Synthetic demo text is explicitly visible. Diagnostics are not replay state.

The historical pre-cleanup automated conformance run passed **205 tests in 18.61 seconds**, including real loopback Redis. Tests use explicit fixture models or mocked HTTP responses to establish contract behavior, not hosted semantic accuracy. Historical actual Laya measurements, live model probes and independently audited workflow artifacts provide separate evidence below.
